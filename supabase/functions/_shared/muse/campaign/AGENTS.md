# Campaign rules

- Campaign social research lives in `campaign_social_profiles` (one row per Instagram/TikTok/Facebook/YouTube), written only by `discover_social_profiles`/`record_social_analysis` in `_shared/muse/campaign/social.ts`; login walls are `not_accessible`, never bypassed, and `agent_campaigns.social_research_complete` is true only when all four platforms are analyzed/not_found/not_accessible — so the agent can never claim a full social analysis it did not do.
- Campaign shot QA is claimed/failed/finalized only via the claim_shot_qa / fail_shot_qa / finalize_shot_qa RPCs (lease, retryable qa_pending, stats once per generation) and reconciled by agent-task-resume without a Muse turn — so a finished video never stays 'generating' and QA re-runs never double-count.
- Shot QA stats count once per generation via qa_stats_contributions (partial unique on valid); bad reviews are retired with invalidate_shot_qa (subtracts only that contribution, archives the verdict), never deleted — so one buggy review can be corrected without touching other stats. Review-only copies live under ai-videos/<user>/qa-derived/ and never replace the original video_url.
- `prepare_shot_retry` plans via pure `_shared/muse/campaign/retryPlan.ts` (failure classes → raised risk → re-ranked router with failed-model penalty → structured prompt rewrite) and refuses wording-only retries (`TRIVIAL_RETRY`) — so a retry always changes something material.
- Shot retries need a `kind='retry'` approval whose `retry_binding` pins campaign, shot, attempt, exact provider request and retry-plan fingerprint (`campaign/retryBinding.ts`), consumed once via `consume_retry_approval`; approval scope and limits are frozen by trigger — so an old or altered approval can never pay for a new attempt.
- Logos found on official sources (`discover_official_logo`, `_shared/muse/campaign/logoDiscovery.ts`) are stored reference_only with source/type/size/confidence; only the owner's `confirm_campaign_logo` RPC (identity + usage rights) makes them reuse_ok, enforced by the `campaign_assets_logo_guard` trigger — so the agent can never self-approve a logo or treat public visibility as permission.
- Manual planning edits go only through `campaign/planningOverrides.ts`: `update_campaign_video_metadata` (whitelisted copy fields of one video) and `override_campaign_shot_routing` (user_approved + reason, planning-state shots only, catalog capability checks, price via the shared `planningEstimate` used by automatic routing); every change appends to the append-only `campaign_planning_audit` and the original automatic decision stays in `routing_rationale.automatic` — so overrides can never bypass capability, pricing or approval rules.
- Phase C assembly runs as one approved, immutable `campaign_assembly_jobs` scope executed by the `agent-task-resume` worker (leased, one provider step = one `campaign_post_actions` row, interrupted steps fail instead of repeating) — so multi-step post-production never depends on chat continuations and "weiter" can never add spending.
- `edit.branding_mode = 'text_only'` drops the logo requirement and logo rendering/probes and requires a text endcard instead — so a missing logo never blocks export and no substitute logo is ever produced.
- The voiceover voice is persisted only via `set_campaign_voiceover_voice` (catalogue-verified id, native for de, user_approved, append-only audit) in `campaign_videos.post_production`; `prepare_spot_assembly` uses an explicit voice_id first, else the confirmed saved one, else NO_VOICE — so a chosen voice never lives only in chat.
- Phase C assembly start/reject happen only via an explicit UI click (chat card or workspace) calling campaign-spot `start_assembly`/`reject_assembly` through `src/services/muse/assemblyClient.ts`; never a Muse tool — so a text reply can never spend money.
- Assembly approval integrity: `scope_fingerprint` = `approvalFingerprint(scope, max_cost)`, checked before start, after the claim and on every worker tick; JSON objects are compared only via `jsonEqual`/`canonicalJson`, never `JSON.stringify` — so jsonb key reordering can't block a valid package and a changed scope or cost always does.
